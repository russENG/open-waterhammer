# セキュリティ境界

Open Waterhammer は計算ロジックと Web UI を公開し、利用者のプロジェクトデータを
ブラウザー内に留める。ソースコードの非公開性をセキュリティ境界としない。

## 保護するもの

- 利用者が入力した管路、施設、地理情報、計算結果
- `.owhproj` に書き出されたプロジェクトデータ
- リリース・デプロイ経路と公開成果物の完全性

## 保護対象ではないもの

- HTML、CSS、TypeScript/JavaScript、Python 計算ロジック、スキーマ、テスト
- 架空データのサンプルと公開資料に基づく数式メタ情報

ブラウザー版は Python ソースを Pyodide へ読み込むため、公開サイトの利用者は計算ロジックを
取得できる。これは AGPL-3.0-or-later と計算の検証可能性に合致する意図した設計である。

## 信頼境界と残るリスク

- プロジェクトデータは IndexedDB に平文で保存される。OS アカウント、ブラウザープロファイル、
  ブラウザー拡張へのアクセスを防ぐものではない。
- 同一オリジンから後日配信されるコードも IndexedDB を読める。公開サイトの供給網侵害は、
  以前保存したデータにも影響し得る。
- 公開サイトは Cloudflare Web Analytics の第三者 JavaScript を実行する。現在の実装はページ閲覧を
  計測し、プロジェクトデータを送信しないが、外部スクリプトには同一ページ上の実行権限がある。
  この残存リスクを許容できない機微データはオフライン版で扱う。
- Content Security Policy は外部送信先を制限する防御であり、同一オリジンの改ざん済みコードを
  検出する仕組みではない。
- `.owhproj` のハッシュは再現性と改変検出の証跡であり、機密性を提供しない。

## 実装する防御

- Pyodide と計算実行コードは自己ホストする。Cloudflare Web Analytics は公開サイトのビルド時のみ注入し、
  ローカル、フォーク、オフライン版には含めない。
- meta CSP でスクリプト、接続先、フレーム、プラグイン、base URL、フォーム送信先を制限する。
- 別ページへの埋め込みを実行時に検出し、作業画面の初期化前に操作を拒否する。
- HTTP ヘッダーを設定できる静的配信環境には `public/_headers` のポリシーを適用する。
- タグ付きリリースごとにオフライン ZIP と SHA-256 チェックサムを公開できる。
- CI で高深刻度以上の本番依存関係アドバイザリを失敗とし、Dependabot で更新を監視する。

## 機微データの利用条件

公開サイトは架空サンプル、学習、一般的な設計比較に用いる。重要インフラの正確な位置、
施設能力、運用条件その他組織が機密と定める情報は、次の条件で扱う。

1. GitHub Release のバージョン固定オフライン版を取得する。
2. 配布ファイルの SHA-256 を公開チェックサムと照合する。
3. 組織内ネットワークまたはオフライン端末から静的配信する。
4. 専用のブラウザープロファイルを使い、不要な拡張機能を無効化する。
5. `.owhproj` の保管・共有は組織の情報管理規程に従う。

## 脆弱性の連絡

公開 Issue に再現手順や実データを書く前に、GitHub リポジトリの Security タブから
private vulnerability report を送信する。その機能が無効な場合は、機密情報を含めずに Issue で
非公開の連絡先を問い合わせる。
