## 1. 結論 — 到達点（最上段・全幅）

リード（1文）:
> 農業用パイプラインの水撃圧計算を、ブラウザだけで実行できる公開実装として整備した。

要旨の三つの目的に対する到達点:

- **① 統一枠組み** — 弁の急閉・緩閉、ポンプ急停止・起動、防護工評価を、技術書 §8.4 の特性曲線法を軸に同じ枠組みで扱える
- **② 条件追跡** — 入力条件・計算条件・結果・変更履歴を対応づけ、条件変更時の再計算と差分比較に対応
- **③ 透明性** — 計算ロジックを公開リポジトリで配布し、自動テスト 295 件で設計基準掲載値との整合を継続確認

**[図1]** `fig1-envelope.png` — ポンプ急停止時の最大・最小水頭分布（防護なし／あり）
Fig.1 Max/min head along pipeline at pump trip (without/with protection device)
（日英キャプションは図に焼き込み済み）

## 2. 背景（要旨 §1）

- 弁操作・ポンプ停止で管内圧力は過渡的に変動。過大圧・負圧の評価は設計段階で必要（技術書 §8.4: 特性曲線法・中心差分法）
- 時代は新設から更新・改修へ。過去の設計根拠を参照した再計算の機会が増加
- 必要なのは、条件と結果を**継続的に追跡・再利用できる計算基盤**
- 現状は閉じた商用ソフト依存が多く、計算式・仮定・数値手法の外部検証が難しい
- 開かれた協働が品質を担保する<sup>2)</sup>・計算ロジックは共有資源<sup>3)</sup>という考えに沿い、公開実装を選択

---

## 3. 目的（要旨 §2）

1. 安全性確認に必要な水撃圧解析を**設計実務者が扱いやすい形**で実装
2. 施設更新・運用変更時の**条件追跡と再計算**を行いやすい構成
3. 条件と結果の一体管理で**透明性・再現性・説明性**を高める

→ 独立検証を可能にし、設計知識の継承と再利用を支える共通基盤へ

---

## 4. 計算機能の構成（要旨 §3）

**アーキテクチャ図（作図する）:**

```
ブラウザ（React UI）
 ├─ Pyodide（WebAssembly）── Python 計算コア（単一の真理源）
 └─ epanet-js（WebAssembly）── EPANET（定常網計算の照合）
```

- インストール不要。計算はすべてブラウザ内で完結し、管路データは外部に送信されない

**機能一覧表:**

| ステップ | 内容 |
|---|---|
| 定常水理計算 | 単管路／管路網（分岐・合流）、測点縦断計算、水理計算書（成果品様式） |
| 水撃圧簡易算定 | Joukowsky／Allievi、急閉・緩閉の判定 |
| 数値解析 | 特性曲線法（樹枝状管路網。弁・ポンプ・防護工の境界条件） |
| 防護工 | エアチャンバ等の有無による応答比較 |
| Excel 入出力 | 管路諸元のテンプレート入力、計算書・帳票の出力 |
| 条件追跡 | セッション保存、変更履歴、ケース間の差分比較 |

## 5. 適用と限界（要旨 §4）

| 区分 | 項目 |
|---|---|
| ✓ 扱える | 単管路の水撃圧簡易算定（Joukowsky／Allievi） |
| ✓ 扱える | 樹枝状管路網の特性曲線法解析、防護工の境界条件 |
| ✓ 扱える | 定常網計算（EPANET との数値照合付き） |
| △ 簡易 | ポンプ特性は簡易モデル（完全4象限特性は未対応） |
| ✗ 対象外 | 水柱分離の再現（DVCM／DGCM 未実装） |
| ✗ 対象外 | ループを含む大規模管路網の非定常解析 |

- 本実装は最大圧力（Hmax）の算定に有効。低圧側は **Hmin = 0 m を水柱分離発生のシグナル**として扱い、設計上は吸気弁・防護工で回避する前提
- 適用限界をそのまま書けることも、公開実装の役割のひとつ

- 式単位の URL 引用が可能（例: `…/#joukowsky`）。設計図書や照査意見のやり取りで、根拠の式を直接指せる

## 7. 検証（品質保証）

- 自動テスト **295 件 全パス**（2026-08-24 時点）
  - TypeScript 計算コア 156 ／ Python 計算コア 108 ／ Excel 入出力 22 ／ EPANET 連携 9
- 技術書掲載の計算例と、関数レベルで整合を確認
- 定常網計算は TypeScript 実装と EPANET の数値一致を確認
- 要旨提出時点で「検証実績のある計算エンジンとの連携が望ましい」とした課題は、**EPANET 連携の実装で対応済み**（要旨提出後の進捗）
